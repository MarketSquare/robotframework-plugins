# Robot Framework Agent Skills

AI agent skills for Robot Framework test automation, distributed for **eight coding agents**: Claude Code, GitHub Copilot CLI, GitHub Copilot in VS Code, OpenAI Codex, Cursor, OpenCode, Project Goose, Claude Desktop. Includes skills for the Robot Framework language (tests, keywords, resources, variables), web testing (Browser/Selenium), API testing (Requests/RESTinstance), mobile testing (Appium), native desktop testing (PlatynUI, preview), and environment setup — plus 3 specialised subagents and validation hooks. It is built to sit next to the RobotCode project's own [`robotcode` plugin](https://github.com/robotcodedev/robotframework-agent-plugins), which teaches agents to drive the robotcode CLI.

**Requires the robotcode CLI** (`robotcode[all]>=2.8`) in the project's Python environment. See [Prerequisites](#prerequisites).

## Install

There are two ways to install, and both work at **user scope** (every project on your machine) or **project scope** (one repository, shared with your team):

- **Plugin marketplace**: Claude Code, GitHub Copilot CLI, VS Code (Copilot), OpenAI Codex and Cursor all read this repository's `.claude-plugin/marketplace.json`. Add the marketplace `MarketSquare/robotframework-plugins` and install the plugin `rf-agentskills`. Updates arrive through the agent.
- **Python installer** (`robotframework-plugins`): copies the files into each agent's own folders. Use it for OpenCode, Goose and Claude Desktop, which have no plugin marketplace, or wherever you prefer plain files. It can also write the marketplace settings for you (`--mode plugin`).

### Plugin marketplace, per agent

| Agent (verified version) | Skills | Subagents | Hooks | Project scope (committed file) |
|---|---|---|---|---|
| **Claude Code** | yes | yes | yes | `.claude/settings.json` enables the plugin |
| **Copilot CLI** (1.0.91) | yes | yes | yes; only validation errors reach the model (see below) | `.claude/settings.json` or `.github/copilot/settings.json` loads the plugin, no install step |
| **VS Code Copilot** (1.142) | yes | yes in the Local harness; not offered in the Copilot harness | yes, with `chat.useHooks`; in the Local harness validation errors reach the model only at the end of the reply (see below) | `.claude/settings.json` recommends the plugin to the workspace |
| **Codex** (0.153.4, 0.161.0) | yes | from the installer | yes, after trusting them once with `/hooks` | none: each user runs the two `codex plugin` commands |
| **Cursor** (CLI 2026.10.01, verified from its plugin loader, not run live) | yes | yes | yes (Cursor converts them) | imports the plugin from Claude Code's `.claude/settings.json` |

The plugin does not set a default main agent. The three subagents are available for delegation, and you can still choose one as your main agent yourself.

**Project scope for your team.** Commit this `.claude/settings.json` (or let `robotframework-plugins install --mode plugin` merge it into the existing file):

```json
{
  "extraKnownMarketplaces": {
    "robotframework-plugins": {
      "source": { "source": "github", "repo": "MarketSquare/robotframework-plugins", "ref": "v3.0.0" }
    }
  },
  "enabledPlugins": {
    "rf-agentskills@robotframework-plugins": true
  }
}
```

Leave out `ref` to follow `main`, or use `stable` for the latest release. Each content release is tagged `v<version>`, and a tag always installs exactly that version.

#### Claude Code

```bash
claude plugin marketplace add MarketSquare/robotframework-plugins       # pin: ...plugins#v3.0.0
claude plugin install rf-agentskills@robotframework-plugins          # --scope user (default) | project | local
# recommended companion: the robotcode plugin
claude plugin marketplace add robotcodedev/robotframework-agent-plugins
claude plugin install robotcode@robotframework-agent-plugins
```

In a session, `/plugin marketplace add …` and `/plugin install …` do the same. `--scope project` writes the committed `.claude/settings.json` above. To try the in-tree plugin without a marketplace: `claude --plugin-dir ./plugins/rf-agentskills`.

#### GitHub Copilot CLI

```bash
copilot plugin marketplace add MarketSquare/robotframework-plugins
copilot plugin install rf-agentskills@robotframework-plugins
# recommended companion: the robotcode plugin
copilot plugin marketplace add robotcodedev/robotframework-agent-plugins
copilot plugin install robotcode@robotframework-agent-plugins
```

That is user scope. For project scope, commit `.claude/settings.json` (or `.github/copilot/settings.json` with the same keys): Copilot CLI loads the plugin in that repository without an install step. Pin a release with its `ref` there.

Copilot CLI passes only a hook's `decision`/`reason` to the model. So the model sees Robot Framework **validation errors** after an edit ("The edit was applied, but …"), but not the advisory context the other agents get: deprecation and formatting warnings, the skill hint on prompts, error hints after `robot` runs, and the session environment report.

#### VS Code (GitHub Copilot)

Plugins and hooks are preview features. In your **user** settings, enable them and add the marketplace:

```json
{
  "chat.plugins.enabled": true,
  "chat.useHooks": true,
  "chat.plugins.marketplaces": ["MarketSquare/robotframework-plugins"]
}
```

Pin with `"MarketSquare/robotframework-plugins#v3.0.0"`. Then install `rf-agentskills` from that marketplace in the Extensions view. For project scope, the committed `.claude/settings.json` recommends the plugin to everyone who opens the workspace (`chat.plugins.marketplaces` itself is a user-only setting). VS Code asks before running hook commands unless your chat approval mode allows them. The [RobotCode extension](https://marketplace.visualstudio.com/items?itemName=d-biehl.robotcode) already bundles the `robotcode` plugin for Copilot Chat, so it needs no separate install.

VS Code 1.142 has two agent harnesses, with different gaps:

- **Copilot** (agent host): validation errors reach the model, but the plugin's three subagents are not offered.
- **Local**: skills and subagents work, but VS Code sends the next model request without waiting for PostToolUse hooks. A validation error first appears only as the banner "A hook prevented chat from continuing". The plugin's Stop hook re-checks the file when the agent finishes its reply and hands the error to the model, which then gets another turn to fix it.

#### OpenAI Codex

```bash
codex plugin marketplace add MarketSquare/robotframework-plugins        # pin: --ref v3.0.0
codex plugin add rf-agentskills@robotframework-plugins
# recommended companion: the robotcode plugin
codex plugin marketplace add robotcodedev/robotframework-agent-plugins
```

Codex has no committed project-scope plugin file: every user runs the two `codex plugin` commands once. The subagents can be committed in `.codex/agents/`.

#### Cursor

Add the marketplace by its git URL, `https://github.com/MarketSquare/robotframework-plugins` (Customize → Plugins, or `cursor-agent plugin marketplace add …`), install `rf-agentskills` and choose project or user scope. Cursor keeps marketplaces on your Cursor account. It also imports the plugin when it is installed in Claude Code or enabled in `.claude/settings.json` (Settings → Third-Party Imports). ### Python installer (`rf-agentskills`)

Run it with zero install and let it walk you through the agents to set up:

```bash
# Zero-install: bare `install` is interactive — multi-select of known agents,
# with the ones detected on your machine pre-checked.
uvx robotframework-plugins install            # or: pipx run robotframework-plugins install

# See what's detected first
uvx robotframework-plugins targets
```

Fully scriptable too — no prompt with an explicit selection, `--yes`, or a non-TTY stdin:

```bash
robotframework-plugins install --agents all                 # every known agent
robotframework-plugins install --agents claude-code,cursor  # explicit list
robotframework-plugins install --agents detected --yes      # only detected, headless
robotframework-plugins install --agent claude-code          # single (back-compat)
robotframework-plugins install --agent claude-code --mode plugin --ref v3.0.0   # marketplace settings instead of files
```

Installs default to **project scope** (into the current directory, e.g. `./.claude/`); add `--scope user` for a global install under your home directory. Other commands: `uninstall`, `list`, `doctor`, `version`. Useful flags: `--scope project|user [--project DIR]`, `--mode files|plugin [--ref TAG]`, `--prefix DIR`, `--dry-run`, `--what skills,agents,hooks`, `--force`, `--no-input`.

`--mode plugin` writes the marketplace entries into `.claude/settings.json` (Claude Code, Copilot, VS Code; Copilot also gets `.github/copilot/settings.json`, or `~/.copilot/settings.json` for user scope), installs the Codex subagents and prints the Codex commands, and prints the Cursor steps. Agents without a marketplace (OpenCode, Goose, Claude Desktop) fall back to files.

A manifest (per-project under `<project>/.rf-agentskills/`, or global for user scope) tracks every file written (hash + transform); `uninstall` removes only files whose hash still matches and only the hook config entries it added — user edits and other tools' hooks are preserved. Re-running `install` after an upgrade removes files the previous install wrote that the new bundle no longer ships (same hash check; user-modified files are kept), including the `rf-tools` MCP server entry and files that installers before content 2.0.0 registered.

| Agent | What lands where (files mode) | Coverage |
|---|---|---|
| **Claude Code** ≥ 2.1 | `~/.claude/skills`, `~/.claude/agents`, `settings.json` hooks | full native |
| **GitHub Copilot** (VS Code ≥ 1.108) | reuses Claude Code paths (Copilot reads them natively) | full native |
| **OpenAI Codex** | `~/.agents/skills` per docs, `~/.codex/agents/*.toml`, `hooks.json` | full (hooks experimental, opt-in via `[features] codex_hooks=true`) |
| **Cursor** ≥ 2.4 | `~/.cursor/skills`, `~/.cursor/agents`, `hooks.json` (namespaced matchers) | full native |
| **OpenCode** | `.opencode/skills`, `.opencode/agents` (`mode: subagent`), `.opencode/plugins/rf-agentskills.js` + hook scripts (or `~/.config/opencode/…`) | skills, subagents; edit validation, error hints and the environment report through the JS plugin (prompt context and the Stop reminder are not ported) |
| **Project Goose** ≥ 1.25 | `~/.agents/skills` (Summon), `.goosehints` persona | skills; subagents folded into hints; hooks N/A |
| **Claude Desktop** | one upload-ready `rf-*.zip` per skill in `~/rf-agentskills-claude-desktop/` | skills via upload (Customize → Skills → Upload a skill; needs code execution); no subagents/hooks |

Release notes, sha256 hashes, and the latest wheel + sdist are on the **[robotframework-plugins releases](https://github.com/MarketSquare/robotframework-plugins/releases)** page (tag prefix `robotframework-plugins-v*`) and on [PyPI](https://pypi.org/project/rf-agentskills/).

The library-reference skills provide documentation and usage guidance; they look keywords up with `robotcode doc`, check files with `robotcode analyze code` and read results with `robotcode results`, written out inline so they work with or without the robotcode plugin. `rf-language` and `rf-python-library` ship a Python script each. ### Automated Hooks

- **Post-save validation**: Checks every written `.robot`/`.resource` file with `robotcode analyze code` (project environment first): syntax, argument and import errors are fed back to the agent; unknown keywords and variables are reported, and block only if still unresolved when the agent finishes; Robocop adds advice: deprecated syntax (`[Return]`, `Run Keyword If`, `Force Tags`, …) is reported as a **non-blocking warning** (`RF_AGENTSKILLS_DEPRECATION_CHECK=warn|off`); an opt-in per-file dry run (`RF_AGENTSKILLS_FILE_DRYRUN=1`). See `plugins/rf-agentskills/hooks/README.md`.
- **Skill routing**: Routes RF-related prompts to the appropriate skill (short routing text, ≤ 450 characters)
- **Environment check**: Checks for Robot Framework, robotcode (≥ 2.8) and the RF packages at session start (install advice via rf-setup)
- **Test reminder**: Reminds you to run tests when the session ends

## Prerequisites

- A supported coding agent (see the install matrix above)
- **Python 3.10+** and **robotframework** in the project environment
- **robotcode[all] 2.8 or later** in the project environment. The skills run `robotcode doc`, `robotcode analyze code`, `robotcode results` and `robotcode robot-debug`, and the validation hooks run `robotcode analyze code`. Install it next to Robot Framework, never with `uvx`, `pipx` or `uv tool` (an isolated robotcode cannot see the project's libraries):

  ```bash
  uv add --dev "robotcode[all]>=2.8"                 # uv
  poetry add --group dev "robotcode[all]>=2.8"       # Poetry
  pip install "robotcode[all]>=2.8"                  # venv + pip (venv active)
  ```

  Why `[all]`: the base package only has `config` and `profiles`; the skills need the `runner` (`robot`, `discover`, `results`), `analyze` and `repl` (`doc`, `robot-debug`) extras, and the hooks need Robocop, which only `[all]` brings in as well. A CI job that only runs tests can use `robotcode[runner]`.
- **Recommended:** the `robotcode` plugin (`robotcode@robotframework-agent-plugins`) next to rf-agentskills. It owns running, discovery, keyword documentation, result analysis, static analysis, `robot.toml` configuration, the REPL and the debugger; rf-agentskills owns Robot Framework syntax, Python keyword libraries, the test-library skills, environment setup, the validation hooks and the design, diagnosis and migration subagents.
- New to Robot Framework setup? The `setup` skill (`rf-setup`) walks an agent through installing it into a project environment (uv preferred; it also covers venv + pip and Poetry).

```bash
uv add robotframework        # pip alternative (inside the project venv): pip install robotframework
```

All scripts handle a missing `robotframework` package gracefully and report how to install it.

Optional libraries (for their respective skills), installed into the project environment -- same commands as the `rf-setup` skill's library table:
```bash
uv add "robotframework-browser[bb]" && uv run rfbrowser install chromium   # Browser skill (no Node.js needed)
uv add robotframework-seleniumlibrary              # Selenium skill (Selenium Manager fetches drivers)
uv add robotframework-appiumlibrary                # Appium skill (+ npm Appium server and drivers)
uv add robotframework-requests                     # Requests skill
uv add RESTinstance                                # RESTinstance skill (Python 3.11+)
uv add --prerelease allow robotframework-PlatynUI  # PlatynUI skill (preview; Python 3.12+; a plain install gets old 0.9.2)
```

## What is an Agent Skill?

Agent Skills are modular, self-contained packages that include a `SKILL.md` file (instructions) plus optional scripts, references, and assets. AI agents load a skill when its name or description matches the user request. Skills use progressive disclosure: only metadata is loaded initially; the full skill body and references are loaded on demand.

## Project Structure

```
.claude-plugin/marketplace.json  # The marketplace every plugin-capable agent reads (generated)
plugins/<name>/                # One folder per plugin; the only copy of its content
├── .claude-plugin/plugin.json # The plugin's one version
├── catalog.yaml               # Programme manifest: tier, status, maintainers, libraries
├── skills/rf-*/               # One folder per skill; folder name == SKILL.md name
│   ├── SKILL.md               # Skill definition (loaded by agent)
│   ├── scripts/               # Python scripts (executed, not loaded)
│   └── references/            # Deep reference docs (loaded on demand)
├── scripts/                   # Hook scripts (.mjs) only
├── agents/                    # Subagent definitions
├── hooks/                     # Session/edit hooks
├── variants/                  # Generated: Codex TOML subagents, OpenCode agents + JS plugin
├── tests/                     # The plugin's own tests (not installed by the installer)
└── evals/                     # Eval tasks, trigger sets and baselines (not installed by the installer)
schemas/catalog.schema.json    # Schema of catalog.yaml
installer/                     # The robotframework-plugins Python installer
tests/                         # Shared tests: repository, catalogue, installer, eval harness
eval/                          # Shared eval harness content: fixture projects and hidden graders
scripts/                       # Build and check utilities
```

Each plugin's folder is the single source of its content; there is no second copy to sync. `scripts/export-skills.py` writes standalone copies for the release tarballs and Claude Desktop archives, with plain `scripts/x.py` commands instead of the plugin's `"${CLAUDE_SKILL_DIR}/scripts/x.py"`. `scripts/build-catalog.py` (also run in CI) validates every `catalog.yaml` and regenerates the marketplace and the catalogue tables. `scripts/check-drift.sh` (also run in CI) checks the generated variants and the plugin layout, and `scripts/validate-skills.py` (also run in CI) checks every `SKILL.md` against the [agentskills.io](https://agentskills.io) frontmatter rules: the folder name equals `name`, which is `rf-<topic>`, plus `license`, `compatibility` and `metadata.version` (= the plugin's `plugin.json` version; kept in step by `scripts/bump-version.sh <plugin> <part>`).

## Development

### After changing a plugin

Edit the files under `plugins/<name>/`. After changing a subagent or `hooks/hooks.json`, regenerate the variants; after changing a `catalog.yaml` or a version, regenerate the catalogue:

```bash
python scripts/build-agent-variants.py
python scripts/build-catalog.py
```

### Checking for Drift

Verify that the generated files and the plugin layout are consistent:

```bash
bash scripts/check-drift.sh
python scripts/build-catalog.py --check
```

Both also run in CI.

### Running Tests

The shared tests and each plugin's tests run separately (plugins may reuse test file names):

```bash
# Shared tests (repository, catalogue, installer)
python -m pytest tests/ --ignore=tests/eval -v

# One plugin's tests
python -m pytest plugins/rf-agentskills/tests/ -v

# Specific test files
python -m pytest plugins/rf-agentskills/tests/test_hook_scripts.py -v       # requires robotcode[all] for the validation tiers
python -m pytest plugins/rf-agentskills/tests/test_rf_conventions.py -v     # requires robotframework
python -m pytest plugins/rf-agentskills/tests/test_script_execution.py -v   # script CLI contract (exit codes, --help, --json-out)
python -m pytest plugins/rf-agentskills/tests/test_skill_commands.py -v     # how SKILL.md / agents / hooks run the scripts
python -m pytest tests/test_drift_detection.py -v
python -m pytest tests/test_marketplace_validation.py -v
python -m pytest tests/test_skill_validation.py -v
```

In a pull request, CI runs the shared tests plus the tests of each plugin the change touches; a change outside `plugins/` runs every plugin's tests (`scripts/select-plugin-tests.py`).

The eval harness (`rf-skill-eval`, `uv run pytest tests/eval`) reads a plugin's eval content from `plugins/<name>/evals/`; pass `--plugin <name>` once more than one plugin has evals.

### Validate the Marketplace and Skills

```bash
python scripts/validate-marketplace.py
python scripts/validate-skills.py --channel all   # root and plugin copies
```

### Bundled scripts

Skills run their Python scripts directly (`uv run python scripts/<name>.py …`, or the project's interpreter); there is no MCP server. Each script prints JSON:

| Script (skill) | Purpose |
|----------------|---------|
| `rf_conventions.py` (rf-language) | Report a project's Robot Framework conventions and version |
| `check_library.py` (rf-python-library) | Check the project's own Python keyword libraries: keywords, scope, API style and defect findings (runs in a subprocess, never imports user code into the agent) |

### Claude Desktop and claude.ai

Claude Desktop loads custom skills uploaded as ZIP files, not from disk. `robotframework-plugins install --agent claude-desktop` writes one archive per skill to `~/rf-agentskills-claude-desktop/` (the CI and release artifacts contain the same archives). Upload each under **Customize → Skills → + → Create skill → Upload a skill** and start a new chat; code execution must be enabled. Build them from a checkout with `python scripts/build-skill-zips.py --out dist/skill-zips`.

### Test the Plugin Locally

```bash
claude --plugin-dir ./plugins/rf-agentskills
```

## Compatibility

- **Robot Framework** 7+ (uses modern syntax: RETURN, IF/ELSE, TRY/EXCEPT)
- **Python** 3.10+ (installer, skill scripts and robotcode)
- **robotcode** 2.8+ with the `all` extra, in the project environment
- **Coding agents** (see the install matrices above): Claude Code ≥ 2.1, GitHub Copilot CLI (plugin verified with 1.0.91), GitHub Copilot in VS Code ≥ 1.108 (plugin verified with 1.138 and 1.142), OpenAI Codex (plugin verified with 0.153.4 and 0.161.0), Cursor ≥ 2.4 (plugin loader checked in CLI 2026.10.01), OpenCode, Project Goose ≥ 1.25, Claude Desktop (skills via ZIP upload)

Anthropic's SKILL.md format is an open standard supported by all eight agents listed above (Claude Code, Copilot, Codex, Cursor, OpenCode, and Goose all read it natively as of their respective recent releases). The `rf-agentskills` installer handles the path-routing per agent so you don't have to memorise where each one wants its skills.

## Running skill evaluations

This repository ships an evaluation harness (`rf-skill-eval`) that grades each
skill under controlled Claude Code sessions and produces a scorecard. See
[docs/ci/usage.md](docs/ci/usage.md) for the full walkthrough. Quick start:

```bash
cp .env.example .env      # add your CLAUDE_CODE_OAUTH_TOKEN
uv sync
uv run rfbrowser init
uv run rf-skill-eval doctor
bash scripts/eval-local.sh
```
