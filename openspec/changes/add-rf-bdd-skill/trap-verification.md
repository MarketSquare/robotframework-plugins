# Trap Verification for rf-bdd Gotchas

Checked on 2026-11-19 with tiny scratch suites, on two tool sets:
- **A (pinned):** Robot Framework 7.4.2, robotcode 2.8.0, Robocop 8.2.10 (worktree `.venv`).
- **B (newer):** Robot Framework 7.5.1 (`uvx --from "robotframework==7.5.1" robot`), Robocop 9.4.0 (`uvx --from "robotframework-robocop>=9.1,<10" robocop`); robotcode 2.8.0 on RF 7.5.1 through `uvx --from "robotcode[all]==2.8.0" --with "robotframework==7.5.1"` where noted.
- DataDriver 1.11.2, installed into a scratch venv (RF 7.4.2, robotcode 2.8.0) and through `uvx --with robotframework-datadriver` for RF 7.5.1.

"Same on A and B" means the output matched line for line.

## Related checks

- Test-level `[Metadata]`: RF 7.4.2 fails the test with `Setting 'Metadata' is not allowed with tests or tasks.`; RF 7.5.1 passes and writes `<meta name="Issue">`.
- robotcode 2.8.0 diagnostics named in the references exist: `VariableNotFound` (undeclared `VAR … scope=TEST` state), `VariableNotReplaced` (hint, `${n}` in a templated test name), `PrivateKeyword` (warning), `MultipleKeywords` (a stricter pattern alone doesn't make a keyword win), `KeywordNotFound`.
- Robocop asset (`assets/robocop-bdd.toml`) on the resource-strategy example: `robocop check` is clean on 8.2.10 and 9.4.0. Removing each lint setting brings back its findings on both versions: `per-file-ignores` (1 VAR06), `pattern='s` (1 NAME02), the NAME18 convention (29 NAME18). So `per-file-ignores` works on 8.2.10.
- Robocop asset, format section: on 8.2.10, `robocop format` stops with `InvalidParameterError: AlignTemplatedTestCases: Failed to import … accepts following arguments: enabled, only_with_headers, min_width`, because `args_with_test` is 9.x only. Without that line, 8.2.10 formats and keeps template values on the test line. `NormalizeSeparators.skip_keyword_call_pattern` works on both versions. On 9.4.0 without `args_with_test=keep`, each example's values move to their own line.
- The inline disabler `# robocop: off=VAR06` on the first line of a resource silences VAR06 on 8.2.10 and 9.4.0.
- MISC04 counts `VAR` as "no `=`" on 9.4.0 only; 8.2.10 doesn't flag a `VAR` next to `${x}=` assignments.
- KW06 exists only in Robocop 9.x.
